# LLM 토큰 사용 이해 가이드

## 토큰이란?

LLM이 텍스트를 읽고 쓰는 단위. 대략 **한글 1글자 ≈ 1~2토큰**, **영문 단어 1개 ≈ 1토큰**.

---

## 화면에 표시되는 숫자

```
모델: qwen3 │ 전송 1228tok → 수신 155tok │ 응답시간 23.9초
You [1383/2048tok] >
```

| 표시 | 의미 |
|------|------|
| **전송 Ntok** | LLM에게 보낸 입력 전체 크기 |
| **수신 Ntok** | LLM이 생성한 응답 크기 |
| **[N/2048tok]** | 전송 + 수신 = 이번 턴의 총 토큰 / 컨텍스트 한도 |

> **[N/2048]은 누적 합계가 아니다.** 매 턴마다 그 턴의 전송+수신으로 갱신된다.

---

## 전송 토큰이 큰 이유

사용자 입력 한 줄이 아니라, **Python 코드가 자동으로 데이터를 조립**해서 보낸다.

```
"일일점검" 입력 (약 5tok)
        ↓  Python이 조립
┌──────────────────────────────────────┐
│ 시스템 프롬프트        ~  50tok      │
│ 서버 메트릭 JSON 데이터  ~ 800tok    │
│ 전일 대비 비교 텍스트    ~ 200tok    │
│ 분석 지시문              ~ 150tok    │
│ 사용자 입력 원문         ~  28tok    │
└──────────────────────────────────────┘
                합계 ≈ 1228tok → LLM 전송
```

사용자 입력은 **트리거** 역할만 하고, 실제 분석 재료는 코드가 붙여서 보낸다.

---

## 기능별 토큰 차이

| 기능 | 전송 | 수신 | 이유 |
|------|------|------|------|
| 일일점검 | ~1228tok | ~155tok | 메트릭 JSON(상세) + 분석 항목 10개 |
| 사용률 예측 | ~944tok | ~386tok | 예측 텍스트(요약) + 분석 항목 36개 |

- **전송이 작은 이유**: 예측은 JSON 원본 대신 요약된 텍스트를 보냄
- **수신이 큰 이유**: 2서버 × 6메트릭 × 3시간대 = 36개 항목을 AI가 설명

---

## 컨텍스트 한도 (2048tok)

```
2048tok = LLM이 한 번에 처리할 수 있는 최대 크기

대화가 길어질수록 전송 토큰이 누적 증가
  → 2048 근접 시 답변 품질 저하 또는 잘림 발생
  → 대화 리셋 또는 context_size 값 증가로 대응
```

### config.yaml 조정

```yaml
llama_cpp:
  context_size: 2048   # 늘리면 더 긴 대화 가능, RAM 사용량 증가
  max_tokens: 512      # 수신(응답) 최대 길이
```

## 한 줄 요약

> **전송 = 내가 보낸 것 전체 (데이터 포함), 수신 = AI가 답한 것, 합계가 2048을 넘으면 안 된다.**
