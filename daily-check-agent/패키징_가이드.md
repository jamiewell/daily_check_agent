# PyInstaller 패키징 가이드 — macOS / Windows

## 핵심 원칙

> **PyInstaller는 크로스 컴파일을 지원하지 않는다.**
> 각 OS에서 실행할 파일은 반드시 해당 OS에서 빌드해야 한다.

| 빌드 OS | 생성 파일 형식 | 확장자 |
|---------|--------------|--------|
| macOS | Unix 실행 파일 (Mach-O) | 없음 (`daily-check-agent`) |
| Windows | Windows 실행 파일 (PE) | `.exe` (`daily-check-agent.exe`) |

> **macOS 에서 빌드한 파일은 Windows 에서 실행 불가. Windows .exe 가 필요하면 Windows PC 에서 직접 빌드해야 한다.**

---

## LLM 백엔드 선택

이 에이전트는 두 가지 LLM 백엔드를 지원한다.

| 항목 | Ollama 모드 | llama.cpp 모드 |
|------|------------|---------------|
| 설치 | Ollama 별도 설치 필요 | 설치 없음 (exe에 포함) |
| 모델 크기 | Qwen3 (수 GB) | Qwen3-0.6B Q4 (~500MB) |
| 저사양 PC | RAM 16GB 이상 권장 | RAM 8GB 이상 가능 |
| 설정 | `config.yaml` ollama 섹션 | `config.yaml` llama_cpp.enabled: true |
| exe 더블클릭 | 별도 Ollama 실행 필요 | llama-server 자동 기동 |

**폐쇄망 데모** 또는 **저사양 Windows PC** 는 llama.cpp 모드를 권장한다.

## Qwen3 모델 비교 — 8B vs 0.6B

### GGUF 란?

**GGUF = GGML Unified Format** — LLM 모델 가중치와 메타데이터를 하나의 파일에 저장하는 포맷.  
llama.cpp 창시자 **Georgi Gerganov**가 2023년 8월에 만들었으며, 재단이나 회사명이 아닌 파일 형식 이름이다.  
Ollama, llama.cpp 기반 모든 런타임이 공통으로 사용한다.

### 모델 스펙 비교

| 항목 | Qwen3-8B (현재 Ollama) | Qwen3-0.6B-Q4_K_M |
|------|----------------------|-------------------|
| 개발사 | Alibaba Cloud (阿里云) | Alibaba Cloud (동일) |
| 파라미터 | **8B** (80억) | **0.6B** (6억) |
| 양자화 | Ollama 기본 (Q4) | Q4_K_M |
| 파일 크기 | 4.9GB | **~380MB** |
| RAM 요구량 | 8GB 이상 | **2GB 이하** |
| 응답속도 (Apple Silicon) | 약 16초 | **약 2~5초** 예상 |
| 답변 품질 | 높음 — 복잡한 분석 가능 | 낮음 — 단순 요약·질의 수준 |
| 적합한 환경 | 개발 PC, 고사양 서버 | 저사양 Windows PC, 데모 |

### Q4_K_M 양자화 의미

```
Q   = Quantization (양자화 — 32bit 부동소수점을 낮은 비트로 압축)
4   = 4비트 (원래 대비 파일 크기 1/4~1/8 수준으로 감소)
K   = K-quants (더 정교한 양자화 알고리즘, 단순 Q4보다 품질 우수)
M   = Medium (S=소형/빠름, M=중간 균형, L=대형/정확)
```

Q4_K_M은 크기와 품질의 균형이 가장 좋아 저사양 데모의 표준 포맷으로 사용된다.

### 용도별 선택 기준

| 상황 | 권장 모델 |
|------|---------|
| 개발 환경 (맥북, 고사양 PC) | Qwen3-8B (Ollama) |
| 임원 데모, 저사양 Windows PC | **Qwen3-0.6B-Q4_K_M** |
| 폐쇄망 반입 (용량 제한) | **Qwen3-0.6B-Q4_K_M** (~380MB) |
| 정확한 장애 원인 분석 필요 | Qwen3-8B (Ollama) |

## macOS — llama.cpp 설치 및 연동 (개발 테스트용)

### 1단계 — llama-server 다운로드

[https://github.com/ggml-org/llama.cpp/releases/latest](https://github.com/ggml-org/llama.cpp/releases/latest) 에서:

| MacBook 종류 | 다운로드 파일 |
|-------------|-------------|
| Apple Silicon (M1/M2/M3/M4) | `llama-bXXXX-bin-macos-arm64.tar.gz` |
| Apple Silicon + 성능 최적화 | `llama-bXXXX-bin-macos-arm64-kleidiai.tar.gz` |
| Intel Mac | `llama-bXXXX-bin-macos-x64.tar.gz` |

### 2단계 — 압축 해제 및 격리 해제

macOS 는 인터넷에서 받은 파일을 자동으로 격리(quarantine)한다. 반드시 해제해야 실행된다.

```bash
# 압축 해제
cd ~/Downloads
tar -xzf llama-bXXXX-bin-macos-arm64-kleidiai.tar.gz

# macOS 격리 속성 제거 (없으면 permission denied 또는 종료코드 137)
xattr -dr com.apple.quarantine ~/Downloads/llama-bXXXX/

# 실행 확인
~/Downloads/llama-bXXXX/llama-server --version
```

### 3단계 — GGUF 모델 확보

**방법 A: Ollama 기설치 모델 재사용 (추가 다운로드 없음)**

Ollama 로 qwen3 이 이미 설치되어 있으면 해당 GGUF 파일을 직접 사용할 수 있다.

```bash
# 모델 manifest 에서 GGUF blob 해시 확인
cat ~/.ollama/models/manifests/registry.ollama.ai/library/qwen3/latest

# "application/vnd.ollama.image.model" 항목의 digest 값 확인
# 예: sha256:a3de86cd...

# blob 파일 경로 (이 파일이 GGUF 파일임)
ls -lh ~/.ollama/models/blobs/sha256-a3de86cd...
```

**방법 B: HuggingFace 에서 경량 모델 다운로드 (저사양용)**

```bash
# Qwen3-0.6B Q4 (~500MB) — 저사양 데모 권장
# https://huggingface.co/Qwen/Qwen3-0.6B-GGUF 에서 직접 다운로드
```

### 4단계 — llama-server 기동

```bash
LLAMA_DIR=~/Downloads/llama-bXXXX
GGUF=~/.ollama/models/blobs/sha256-<모델해시>   # 또는 .gguf 파일 경로

DYLD_LIBRARY_PATH="$LLAMA_DIR" \
"$LLAMA_DIR/llama-server" \
  -m "$GGUF" \
  --host 127.0.0.1 \
  --port 8080 \
  -c 2048 \
  -ngl 99 \        # Apple Silicon Metal GPU 가속 (모든 레이어 GPU 로)
  --log-disable &

# 서버 기동 확인 (30~60초 소요)
until curl -s http://127.0.0.1:8080/health | grep -q ok; do sleep 2; done
echo "서버 준비 완료"
```

### 5단계 — config.yaml 에서 llama.cpp 모드 활성화

```yaml
llama_cpp:
  enabled: true          # false → true
  host: "127.0.0.1"
  port: 8080
```

### 6단계 — 에이전트 실행

```bash
cd daily-check-agent
source .venv/bin/activate

python3 main.py analyze   # AI 분석
python3 main.py chat      # 대화 모드
```

> **동작 확인 결과 (b9190, Qwen3-8B, Apple M 시리즈)**
> - analyze 응답시간: 약 16초
> - chat 응답시간: 약 13초
> - Metal GPU 가속(-ngl 99) 사용 시 CPU-only 대비 3~5배 빠름

### exe 더블클릭 동작

exe 를 더블클릭하면 인자 없이 실행되므로 **analyze 모드가 자동 실행**된다.

```
daily-check-agent.exe 더블클릭
→ llama-server.exe 자동 기동 (llama.cpp 모드인 경우)
→ 메트릭 로딩
→ AI 분석 결과 출력
→ 종료 시 llama-server 자동 종료
```

#### 동작 원리 — `main.py` 의 기본 모드 결정 로직

```python
# main.py 상단 — exe 더블클릭(인자 없음) 시 analyze 모드 자동 실행
if getattr(sys, 'frozen', False) and len(sys.argv) == 1:
    sys.argv.append('analyze')
```

| 조건 | 설명 |
|------|------|
| `sys.frozen == True` | PyInstaller 로 패키징된 exe 로 실행 중임을 나타내는 플래그 |
| `len(sys.argv) == 1` | 사용자가 인자를 전달하지 않은 상태 (더블클릭) |
| `sys.argv.append('analyze')` | CLI 인자로 `analyze` 를 주입 — 이후 Click 이 그대로 처리 |

- `python3 main.py` 로 직접 실행할 때는 `frozen` 플래그가 없으므로 이 코드는 실행되지 않는다.
- exe 에 명시적 인자를 주면 (`daily-check-agent.exe chat`) 이 코드는 건너뛰고 그대로 처리된다.

#### 기본 모드 변경 방법

더블클릭 시 다른 모드로 실행하고 싶다면 `main.py` 의 해당 줄만 수정하면 된다.

```python
# analyze 대신 chat 으로 변경 (대화형으로 시작)
if getattr(sys, 'frozen', False) and len(sys.argv) == 1:
    sys.argv.append('chat')

# analyze 실행 후 리포트도 자동 저장하고 싶은 경우
if getattr(sys, 'frozen', False) and len(sys.argv) == 1:
    sys.argv += ['analyze', '--save']
```

| 원하는 동작 | `sys.argv.append(...)` 값 |
|------------|--------------------------|
| AI 분석만 출력 (기본) | `'analyze'` |
| AI 분석 + 리포트 파일 저장 | `['analyze', '--save']` (리스트로 확장) |
| 대화형 모드로 시작 | `'chat'` |
| 빠른 상태 확인 (LLM 없음) | `'check'` |
| 사용률 예측 | `'predict'` |

수정 후 `build.bat` (Windows) 또는 `build.sh` (macOS) 를 다시 실행하면 반영된다.

├── OllamaSetup.exe           ← https://ollama.com/download 에서 다운로드

## 주의사항

| 항목 | 내용 |
|------|------|
| 플랫폼 분리 | macOS 빌드 ≠ Windows 빌드, 반드시 각 OS 에서 빌드 |
| .exe 형식 | Windows 전용. macOS 빌드 결과물은 .exe 가 아님 |
| `_internal\` | Python 런타임 폴더, 이동하거나 수정하면 실행 불가 |
| 실행 위치 | `dist\daily-check-agent\` 폴더 안에서 실행 (config.yaml 이 있는 폴더) |
| `config.yaml` | Grafana URL / 토큰, llama_cpp.enabled 등 배포 전 반드시 편집 |
| AV 오탐 | PyInstaller .exe 를 일부 백신이 오탐 가능, UPX 비활성화로 완화 적용됨 |
| Python 버전 | Python 3.10~3.12 권장. 3.13 은 일부 라이브러리 호환 문제 가능 |
