# 사용률 예측 기능 정의

> MVP 에이전트 추가 기능 — 전일 24h 시계열 데이터 기반 사용률 예측 (slope A/B/C 방식)

---

## 1. 개요

서버의 CPU·메모리·디스크·네트워크 사용률을 **전일 24시간 시간별 평균값**으로 기준선(baseline)을 설정하고,  
세 가지 slope(A/B/C)를 계산하여 향후 1h / 3h / 6h 사용률과 임계치 도달 시점을 예측한다.

---

## 2. 알고리즘

### 2-1. 기준선 (Baseline)

```
baseline = mean(전일 00~23시 시간별 값, 24개)
```

24시간 평균. 방향성 없이 "이 서버는 평소 이 정도 사용률"을 나타내는 기준점.

---

### 2-2. Slope 세 종류

예측 시점 T = 현재 시각(시 단위), 예측 구간 = h시간

| 이름 | 계산 구간 | 의미 |
|---|---|---|
| **slope_A** | 오늘 T 직전 N포인트 (5분 간격) | 현재 진입 추세 — 지금 올라오는 중인지/내려가는 중인지 |
| **slope_B** | 전일 (T-3h) ~ T 시간별 값 | 과거 동일 시각 직전 패턴 — 어제 같은 시각에도 같은 방향이었는지 |
| **slope_C** | 전일 T ~ (T+h) 시간별 값 | 과거 동일 시각 이후 패턴 — 어제 이 시간 이후 어떻게 움직였는지 |

**slope_C가 예측의 핵심**: 어제 같은 시간 이후에 사용률이 오르면, 오늘도 오를 가능성이 높다.

---

### 2-3. 선형 회귀 (순수 Python, 외부 라이브러리 없음)

```
slope = Σ((xᵢ - x̄)(yᵢ - ȳ)) / Σ((xᵢ - x̄)²)
```

- 인덱스(0, 1, 2 …)를 x축, 메트릭 값을 y축으로 최소제곱법 적용
- slope_A: 5분 단위 데이터이므로 `slope × 12`로 시간당 환산
- slope_B/C: 1시간 단위 데이터이므로 변환 없이 사용
- r² < 0.3이면 "불규칙(노이즈)" 표기 — 방향 판단 신뢰도 낮음

---

### 2-4. 방향 판단 기준

```
threshold = baseline × 0.005   (기준선의 0.5%/h)

slope > threshold  → 우상향 ↑
slope < -threshold → 우하향 ↓
그 외              → 횡보   →
```

---

### 2-5. 예측값 계산

```
predicted[h] = max(0, current_value + slope_C[h] × h)
```

- `current_value`: 오늘 데이터의 최신 측정값
- `slope_C[h]`: 전일 T ~ T+h 구간의 시간당 기울기
- 음수 방지를 위해 max(0, …) 적용

---

### 2-6. 임계치 도달 예상 시간

slope_C > 0이고 현재값이 주의 임계치 미만일 때:

```
threshold_reach_h = (warn_threshold - current_value) / slope_C
```

## 3. 데이터 구조

### 3-1. 전일 24h 샘플 데이터 (`sample_data/forecast/`)

```json
{
  "server": "prautap1",
  "date": "2026-05-16",
  "interval": "1h",
  "metrics": {
    "cpu_pct":         [5.8, 5.5, ..., 5.9],   // 00~23시 24개
    "mem_pct":         [13.2, 13.1, ..., 13.8],
    "rx_mbps":         [0.5, 0.3, ..., 0.6],
    "tx_mbps":         [0.3, 0.2, ..., 0.4],
    "disk_read_mbps":  [0.02, 0.01, ..., 0.02],
    "disk_write_mbps": [0.5, 0.4, ..., 0.5]
  }
}
```

실 운영 시에는 Grafana API에서 `range_minutes: 1440`, 1h 집계로 조회.

### 3-2. MetricForecast 객체 (src/forecaster.py)

| 필드 | 타입 | 설명 |
|---|---|---|
| `baseline` | float | 전일 24h 평균 |
| `current_value` | float | 현재 측정값 |
| `slope_a` | SlopeInfo | 오늘 진입 추세 (slope, direction, r²) |
| `slope_b` | SlopeInfo | 전일 동일 진입 추세 |
| `slope_c` | dict[h→SlopeInfo] | 전일 이후 패턴 (h=1,3,6) |
| `predicted` | dict[h→float] | 예측값 |
| `risk` | dict[h→str] | 정상/주의/위험 |
| `threshold_reach_h` | float\|None | 임계치 도달 예상 시간 |

## 4. 사용 방법

### 4-1. CLI 명령

```bash
# 전체 메트릭 예측 (LLM 해석 포함)
python main.py predict

# 특정 메트릭만
python main.py predict --metric cpu
python main.py predict --metric memory
python main.py predict --metric network
python main.py predict --metric disk

# 예측 구간 변경 (기본: 1h, 3h, 6h)
python main.py predict --horizon 1,6,12

# LLM 해석 생략 (빠른 수치 확인만)
python main.py predict --no-llm
```

### 4-2. Chat 모드 키워드

| 입력 예시 | 동작 |
|---|---|
| `예측해줘` | 전체 메트릭 1h/3h/6h 예측 + AI 해석 |
| `사용률 예측` | 동일 |
| `트렌드 분석해줘` | 동일 |
| `앞으로 어떻게 될까?` | 동일 |

## 7. 확장 방향

- **Grafana API 연동**: `range_minutes: 1440` + `step: 1h` PromQL로 실데이터 조회
- **예측 구간 확장**: `--horizon 12,24` 로 장기 예측
- **이상 패턴 감지**: slope_A ≠ slope_B 이면 "어제와 다른 패턴" 경보
- **다중 서버 비교**: 동일 메트릭 여러 서버 한눈에 비교
